# Design philosophy — หลักปรัชญาการออกแบบ Neuron flow

**Set by the project owner on 2026-11-01. It may change later.** Use it as the compass for every new
feature; if a feature goes against it, write down why.

## In short (English)

1. **Plain language outside, deep work inside.** People talk to the system in everyday words, including
   metaphors. Inside, the work is structured, checked and auditable.
2. **Understand, then elaborate on request.** Answer in layers: one-line summary → steps → technical detail.
3. **Stay inside the frame.** The frame is versioned data, not just a sentence in a prompt. "Out of scope"
   is a valid, honest answer.
4. **AI proposes, code verifies, people decide what matters.**
5. **No perfectionism.** Small measured steps; state uncertainty honestly.
6. **Equitable support, offered without being asked.** When someone starts talking about technology or
   logic systems, the first response gives study resources: what each one is for, its level, and which
   topics to study first.

The rest of this file is in Thai, the owner's working language.

## ถ้อยคำของเจ้าของโปรเจกต์

> เป้าหมายเชิงปรัชญา: ระบบต้องสามารถเข้าใจภาษาธรรมพื้นฐาน สามารถขยายความได้ โดยมั่นใจว่าบริบทจะไม่ออกนอกกรอบ สามารถสื่อสารด้วยภาษาธรรมดาแต่ทำงานได้ในระดับลึกซึ้งในตัวเอง

> นิสัยความมุ่งมั่นของโมเดล ไม่ใช่การต้องการสร้างความสมบูรณ์แบบให้ผู้ใช้ แต่เป็นโมเดลที่ยืดหยุ่น พร้อมสนับสนุนทักษะให้เสมอภาค โดยที่ผู้ใช้ไม่ต้องเรียกร้องก่อน โมเดลจะตอบสนองเองได้ทันที เมื่อมีหัวข้อกระตุ้นให้ออกแบบระบบ โมเดลนี้จะให้คำแนะนำ และแหล่งข้อมูลสำหรับศึกษา

> การตอบสนองแรกของระบบ เมื่อผู้ใช้เริ่มพูดถึงเทคโนโลยี หรือระบบตรรกะ ด้วยภาษาธรรมดาทั่วไป เชิงเปรียบเปรย โมเดลจะหาแหล่งข้อมูลสำหรับศึกษา พร้อมคำอธิบายในแต่ละแหล่งว่ามีไว้สำหรับอะไร และขั้นตอนในการศึกษาควรให้ความสำคัญที่หัวข้อไหน

**หมายเหตุจากเจ้าของโปรเจกต์:** "ภาษาธรรม" ในถ้อยคำข้างบนหมายถึง **ภาษาธรรมดาทั่วไป** ที่คนพูดกันในชีวิตประจำวัน

## ความหมายที่ใช้ในการออกแบบ

1. **ภายนอกคุยด้วยภาษาธรรมดา ภายในทำงานลึก** คุยด้วยคำที่คนทั่วไปใช้ แต่ข้างในทำงานแบบมีโครงสร้าง ตรวจสอบได้ และลึก
2. **เข้าใจภาษาธรรมดาทั่วไป รวมถึงคำเปรียบเปรย** สั่งงานได้โดยไม่ต้องใช้ศัพท์เทคนิค และต้องเข้าใจว่าคำพูดที่ต่างกันอาจหมายถึงเรื่องเดียวกัน เช่น "เข้าระบบไม่ได้" กับ "ล็อกอินไม่ผ่าน" ไม่ว่าจะเขียนภาษาไทยหรืออังกฤษ
3. **ขยายความได้เมื่อถูกขอ** ตอบเป็นชั้น คือสรุป 1 บรรทัด → ขั้นตอน → รายละเอียดเชิงเทคนิค
4. **ไม่ออกนอกกรอบ** กรอบงานต้องเป็นข้อมูลที่มีเวอร์ชัน ไม่ใช่แค่ประโยคใน prompt ถ้าเรื่องอยู่นอกกรอบ ให้บอกตรง ๆ ว่าช่วยอะไรได้ ไม่เดาเอง
5. **AI เสนอ ระบบตรวจ คนตัดสินเรื่องสำคัญ** ความลึกข้างในต้องพิสูจน์ได้ด้วยการตรวจอัตโนมัติ ไม่ใช่พึ่งความเชื่อใจ AI
6. **ไม่ไล่ความสมบูรณ์แบบ** ทำทีละน้อย วัดผล ปรับ และบอกความไม่แน่ใจตรง ๆ (ระดับความมั่นใจ ต่ำ/กลาง/สูง)
7. **สนับสนุนทุกคนอย่างเสมอภาค** ไม่บังคับให้ใช้ศัพท์เทคนิค ปรับระดับคำอธิบายตามผู้ใช้ ใช้ภาษาไทยได้ และเสนอความช่วยเหลือเองโดยไม่ต้องรอให้ขอ

## กฎการตอบสนองแรก: เมื่อผู้ใช้เริ่มพูดถึงเทคโนโลยีหรือระบบตรรกะ

ใช้เมื่อผู้ใช้เริ่มพูดถึงเรื่องเทคโนโลยีหรือระบบตรรกะด้วยภาษาธรรมดาหรือคำเปรียบเปรย เช่น "อยากให้ระบบเป็นเหมือนบรรณารักษ์ที่รู้ใจ"

1. **ถอดคำเปรียบ** หาว่าเบื้องหลังคำพูดคือหัวข้ออะไร เช่น บรรณารักษ์ที่รู้ใจ → ระบบที่เข้าใจความต้องการ + ระบบแนะนำ
2. **เล่ากลับให้ตรงกัน** บอกหัวข้อเป็นภาษาธรรมดา พร้อมชื่อทางเทคนิคในวงเล็บ ถ้าไม่มั่นใจ ให้ถามยืนยัน 1 คำถาม
3. **แนะนำแหล่งศึกษา 3–5 แหล่ง** บอกทุกแหล่งว่า **ใช้ทำอะไร** **ระดับ** (เริ่มต้น/กลาง/ลึก) และ **ภาษา** ถ้ามีแหล่งภาษาไทยให้ใส่ด้วย
4. **วางลำดับการศึกษา** บอกว่าเริ่มที่ไหน หัวข้อไหนสำคัญที่สุด ส่วนไหนข้ามไปก่อนได้ โดยเรียงจากง่ายไปยาก
5. **ทำงานที่ผู้ใช้ขอต่อ** การแนะนำแหล่งเรียนต้องไม่ขวางงานจริง

**กติกาคุณภาพ**
- ใช้ลิงก์จากคลังแหล่งความรู้ที่ตรวจแล้ว หรือลิงก์ที่ตรวจว่ามีอยู่จริงในขณะนั้นเท่านั้น ห้ามเดาลิงก์
- แนะนำไม่เกิน 5 แหล่ง และตัดข้อมูลที่แค่ "น่ารู้" ออก มือใหม่จะได้ไม่ท่วมท้น ตามหลักทฤษฎีภาระทางปัญญา (cognitive load)
- บอกเหตุผลว่าทำไมแนะนำแหล่งนี้ และทำไมเรียงลำดับแบบนี้
- AI ยังตีความคำเปรียบพลาดได้ (มักดูแค่คำผิวเผิน) จึงต้องเล่ากลับให้ผู้ใช้ยืนยันในข้อ 2 และต้องมีชุดทดสอบคำเปรียบภาษาไทยของเราเอง

## ลำดับการทำงานเมื่อมีคำสั่งภาษาธรรมดาเข้ามา

1. **รับข้อความ** ที่เป็นภาษาธรรมดา ภาษาไทยหรืออังกฤษก็ได้
2. **ถอดความหมาย** AI แปลงเป็น "งานที่ระบบรู้จัก" จากสมุดงานที่มีเวอร์ชัน พร้อมระดับความมั่นใจ
3. **ตรวจกรอบ** ระบบตรวจว่างานอยู่ในสมุดงานและข้อมูลครบ ถ้าอยู่นอกกรอบ ให้บอกตรง ๆ ถ้าข้อมูลขาด ให้ถามกลับ 1 คำถามง่าย ๆ
4. **ทำงานลึกข้างใน** Core จัดลำดับขั้น ตรวจผลทุกขั้น ลองใหม่ กู้คืน และเก็บหลักฐาน
5. **ตอบเป็นภาษาธรรมดา** สรุปก่อน แล้วขยายความเมื่อผู้ใช้ขอ
6. **เสนอเอง** ถ้าเป็นการเริ่มพูดถึงเทคโนโลยีหรือระบบตรรกะ ให้ใช้ "กฎการตอบสนองแรก" ข้างบน

## สถานะเทียบกับหลัก (1 พ.ย. 2026)

- **มีแล้ว (รอบแรก, PR #9):**
  - ถอดความหมายแบบแคบ คือข้อความเคส → 4 หมวด
  - กันคำสั่งแอบแฝงในข้อความ
  - ตรวจผลทุกขั้น
  - คนตัดสินเสมอ
  - บันทึกที่มาของคำตอบ AI
  - บอกระดับความมั่นใจ
  - ชุดเคสภาษาไทยและอังกฤษ
- **ยังขาด:**
  - สมุดงานที่กว้างกว่าการคัดแยกเคส
  - คำตอบ "นอกกรอบ" ที่ชัดเจน พร้อมเคสทดสอบนอกกรอบ
  - การถามกลับเมื่อข้อมูลไม่พอ
  - คำอธิบายแบบหลายชั้น
  - การตอบสนองแรกแบบแนะนำแหล่งเรียน (`study_guide.v1`) และคลังแหล่งความรู้ที่ตรวจแล้ว

## แผนสร้าง `study_guide.v1` (ข้อเสนอ ยังไม่ได้สร้าง)

ใช้แนวเดียวกับรอบแรก และไม่แตะ Core

1. `detect_topic` (AI) ถอดคำเปรียบเป็นหัวข้อจากแคตตาล็อกหัวข้อที่มีเวอร์ชัน พร้อมระดับความมั่นใจ หรือตอบว่า "นอกกรอบ"
2. `pick_resources` (กฎ) เลือกแหล่งจากคลังที่ตรวจแล้ว แต่ละแหล่งระบุว่าใช้ทำอะไร ระดับ ภาษา และหัวข้อที่ควรเน้น
3. `build_path` (กฎ) เรียงตามความรู้ที่ต้องมีก่อนและตามระดับ เริ่มจากง่าย และให้ภาษาไทยมาก่อนถ้ามี
4. `explain` (AI) เขียนคำอธิบายเป็นภาษาธรรมดา โดยอ้างได้เฉพาะแหล่งที่ถูกเลือก
5. ตัวตรวจ ทุกลิงก์ต้องอยู่ในคลัง แนะนำไม่เกิน 5 แหล่ง ทุกแหล่งมีคำอธิบายว่าใช้ทำอะไร และทุกขั้นอ้างถึงแหล่งที่เลือกจริง
6. วัดผลด้วยชุดประโยคเปรียบเปรยภาษาไทยและอังกฤษ รวมถึงประโยคนอกกรอบ
