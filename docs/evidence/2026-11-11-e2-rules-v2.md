## Design and measurement boundary

- `case_triage.v2` uses `triage.classify_rules` with `keywords-v2:50f64599c8980562ae81e60bcd9f62cdd8e836ab8eb533cfff631e6ed5358d3a`. The version tags the matching algorithm and the SHA-256 of the exact JSON bytes.
- NFKC and lower case, Latin accent removal, selected zero-width and soft-hyphen removal, hyphens tried as spaces and joined; English explicit whole-word forms, Thai substrings. The original input is unchanged; precedence remains access, upload, billing, other.
- The rules-only `case_triage.v1` keeps the original `keywords-v1` demonstration. This explicitly supersedes PR #62's unimplemented shared-agent proposal: separate agent names keep both registries compatible and preserve the demonstration.
- The held-out file was committed in `a30de92` before the rules changed, then merged unchanged into this branch. PR #62 recorded that its developer had already seen the v1 mistakes. The rules implementation and integration workers did not read it. The rule data was frozen at the hash above before this session evaluated it; no keyword was changed after that evaluation. It is a developer-authored held-out set, not an independent test of real-world accuracy.
- No Core, prompt, mock-provider, existing label or existing case text changed. The held-out file is the unchanged addition from PR #62. Rules suggest and AI gives a second opinion; human approval is always required.
