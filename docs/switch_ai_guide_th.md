# วิธีเปิด ปิด และเปลี่ยน AI ของหน้าเว็บจริง (ทีละขั้น)

**สรุปบรรทัดเดียว:** เปิด AI จริง (Typhoon) ให้หน้าเว็บได้ด้วยการเพิ่ม 2 แถวใน Render และเปลี่ยนกลับได้ทุกเมื่อด้วยการลบ 1 แถว
ไม่ต้องแก้โค้ด ไม่ต้องรวม (merge) อะไร ใช้เวลาครั้งละราว 2 นาที

เอกสารนี้เขียนให้เจ้าของโปรเจกต์ทำเองได้ด้วยการคลิก ไม่ต้องรันคำสั่งใด ๆ
(English: how the owner switches the live page between the mock AI, Typhoon and Claude in Render's Environment tab. Roadmap 0.4.)

## ก่อนเริ่ม: 4 ข้อที่ต้องรู้

1. **พิมพ์ได้เฉพาะข้อมูลสมมุติ** เมื่อเปิด Typhoon ข้อความที่พิมพ์บนหน้าเว็บจะถูกส่งไปที่ Typhoon (หลังปิดข้อมูลส่วนตัวที่จับรูปแบบได้)
   และ Typhoon เก็บข้อมูลการใช้งานไปปรับปรุงโมเดล ห้ามพิมพ์ข้อมูลจริงของลูกค้า
2. **ทุกครั้งที่กด Save ใน Render ระบบจะเริ่มใหม่ 1–2 นาที** และบนแผนฟรี เคสที่ค้างอยู่ในคิวจะหาย ทำตอนที่ไม่มีเคสค้างจะดีที่สุด
3. **อย่าแก้หรือลบแถว `NEURON_FLOW_ACCESS_KEY`** ถ้าแถวนี้หาย หน้าเว็บจะเปิดไม่ได้ (ตอบ 503) จนกว่าจะใส่คืน
4. **คีย์ของ Typhoon ใส่ใน Render เท่านั้น** อย่าส่งคีย์ในแชต อย่าใส่ในไฟล์ของโปรเจกต์ และ Claude Code ไม่เห็นคีย์นี้ จึงใส่แทนคุณไม่ได้

## ส่วน A: เปิด Typhoon

1. **เตรียมคีย์ของ Typhoon**
   - ถ้าคุณเก็บคีย์ที่สร้างไว้เมื่อ 6 พ.ย. ใช้คีย์นั้นได้เลย
   - ถ้าไม่ได้เก็บไว้ เปิด https://opentyphoon.ai เข้าสู่ระบบ แล้วไปหน้าที่แสดง API key เพื่อคัดลอกหรือสร้างคีย์ใหม่
     (ชื่อเมนูบนเว็บอาจเปลี่ยนได้ ผมเปิดเว็บนี้ตรวจจากเซสชันไม่ได้)
   - ถ้าเว็บแจ้งว่าคีย์เก่าถูกยกเลิกเมื่อสร้างคีย์ใหม่ ให้บอกผมด้วย เพราะปุ่มวัดผลใน GitHub Actions ใช้คีย์เก่าอยู่ และต้องเปลี่ยนตาม
2. เปิด https://dashboard.render.com → คลิกบริการ **neuron-flow** → แท็บ **Environment**
3. กดเพิ่มตัวแปร (Add Environment Variable) **เป็นแถวใหม่** 2 แถว:

   | ช่อง Key | ช่อง Value |
   |---|---|
   | `TYPHOON_API_KEY` | วางคีย์ของ Typhoon |
   | `NEURON_FLOW_LLM_PROVIDER` | `typhoon` |

4. กด **Save** (ปุ่มอาจเขียนว่า Save Changes หรือ Save, rebuild, and deploy) แล้วรอ 1–2 นาที
5. **ตรวจว่าเปิดสำเร็จ:** เปิด https://neuron-flow.onrender.com → แท็บ **ตั้งค่า** → กรอบ "AI ที่ใช้อยู่"
   - ผู้ให้บริการต้องขึ้นว่า **Typhoon (typhoon)** และสถานะ **พร้อม**
   - ถ้าขึ้นว่า "ตั้งค่าไม่ครบ" แปลว่าแถว `TYPHOON_API_KEY` ยังไม่มี หรือสะกดชื่อผิด กลับไปแก้ในข้อ 3
6. **ลองส่งเคส:** เลือก "เคสลูกค้า" พิมพ์ `ทำบัตรหาย แล้วมีรายการที่ผมไม่ได้ทำ` แล้วกด "ยืนยันและส่ง"
   - แถว "ความเห็นที่สอง" ต้องขึ้นชื่อ **Typhoon** (ไม่ใช่ "AI จำลอง")
   - หลังรวม PR #67 แล้ว อาจเห็นเหตุผลเพิ่มว่า "AI เห็นว่าควรดูก่อน: …" ด้วย
   - เคสยังรอคุณกดตัดสินเหมือนเดิม
7. บอกผมว่า "เปิดแล้ว" ผมจะเปิดดูบันทึกการทำงาน (log) ของ Render และ Sentry ให้ว่ามีข้อผิดพลาดหรือไม่

## ส่วน B: กลับไปใช้ AI จำลอง (ปิด Typhoon)

1. Render → บริการ **neuron-flow** → แท็บ **Environment**
2. ลบแถว `NEURON_FLOW_LLM_PROVIDER` (หรือแก้ค่าเป็น `mock`) แล้วกด **Save**
3. รอ 1–2 นาที แล้วดูแท็บ **ตั้งค่า** ของหน้าเว็บ ผู้ให้บริการต้องกลับเป็น "AI จำลอง (mock)"

แถว `TYPHOON_API_KEY` จะเก็บไว้หรือลบก็ได้ ถ้าไม่มีแถว `NEURON_FLOW_LLM_PROVIDER` ระบบจะไม่ใช้คีย์นี้

## ส่วน C: เปลี่ยนไปใช้ AI ตัวอื่นในอนาคต

- **Claude (มีค่าใช้จ่าย เป็นการตัดสินใจ D2 ของคุณ):** แก้ค่าแถว `NEURON_FLOW_LLM_PROVIDER` เป็น `anthropic`
  แล้วเพิ่มแถว `ANTHROPIC_API_KEY` (คีย์จาก Claude Console) กด Save แล้วตรวจแบบเดียวกับส่วน A ข้อ 5–6
  ยังไม่เคยวัดผลกับ Claude ในโปรเจกต์นี้ ควรให้ผมรันวัดผลก่อนเปิดใช้จริง
- **Typhoon รุ่นอื่น:** เพิ่มแถว `NEURON_FLOW_LLM_MODEL` แล้วใส่ชื่อรุ่น ถ้าไม่มีแถวนี้ ระบบใช้รุ่น `typhoon-v2.5-30b-a3b-instruct`
  ซึ่งเป็นรุ่นที่วัดผลไว้ ถ้าจะเปลี่ยนรุ่น ควรให้ผมวัดผลรุ่นใหม่ก่อน
- ทุกครั้งที่เปลี่ยน AI หรือรุ่น ระบบนับเป็น "รุ่นใหม่ของตัวทำงาน" เคสที่ค้างกลางทางจะล้มเหลวพร้อมเหตุผล "ตั้งค่าเปลี่ยนหลังรับเคส" ซึ่งตั้งใจให้เป็นแบบนั้น

## เมื่อ Typhoon ช้าหรือล่ม จะเกิดอะไรขึ้น

- ระบบลองถาม AI ซ้ำ 1 ครั้ง ถ้ายังไม่ได้ เคสจะไปถึงคนตรวจด้วยข้อเสนอของกฎ และหน้าเว็บบอกว่า "AI ใช้งานไม่ได้ตอนนั้น"
- สัญญาณ "ต้องให้คนดูก่อน" ของโค้ดยังทำงานตามปกติ เพราะไม่ได้ใช้ AI
- ที่วัดไว้เมื่อ 11 พ.ย.: Typhoon ไม่ตอบ 8 จาก 1,780 เคส และเคยล่มราว 1 ชั่วโมง ([บันทึกหลักฐาน](evidence/2026-11-11-attention-signals.md))
- เคสแรกหลังระบบตื่นอาจช้ากว่าปกติ และ Typhoon มีเพดานจำนวนคำขอต่อนาที ถ้าส่งเคสถี่มากอาจเห็น "AI ใช้งานไม่ได้" ได้

## ถ้ามีปัญหา

| อาการ | สาเหตุที่พบบ่อย | วิธีแก้ |
|---|---|---|
| แท็บตั้งค่าขึ้น "ตั้งค่าไม่ครบ" | ไม่มีแถว `TYPHOON_API_KEY` หรือสะกดผิด | เพิ่มหรือแก้ชื่อแถวให้ตรง แล้ว Save |
| ทุกเคสขึ้น "AI ใช้งานไม่ได้" | คีย์ผิด คีย์ถูกยกเลิก หรือ Typhoon ล่ม | ลองใหม่ภายหลัง ถ้ายังเป็น ให้ใส่คีย์ใหม่ หรือกลับไปส่วน B แล้วบอกผม |
| หน้าเว็บเปิดไม่ได้ หรือถามรหัสเข้าใช้ใหม่แล้วรหัสเดิมใช้ไม่ได้ | แถว `NEURON_FLOW_ACCESS_KEY` ถูกลบหรือถูกสร้างใหม่ | เปิดแท็บ Environment คัดลอกค่าของ `NEURON_FLOW_ACCESS_KEY` มาใส่ในหน้าเว็บใหม่ ถ้าแถวหาย บอกผม |
| เคสที่ส่งไว้หาย | ระบบเริ่มใหม่หลังกด Save (แผนฟรีไม่มีที่เก็บถาวร) | ส่งเคสใหม่ เป็นข้อจำกัดของแผนฟรี (เรื่องที่ต้องตัดสินใจ D1) |

## สิ่งที่ Claude Code ทำแทนได้ และทำแทนไม่ได้

- **ทำแทนไม่ได้:** ใส่คีย์ของ Typhoon ใน Render เพราะผมไม่เห็นคีย์ และไม่ควรเห็น
- **ทำได้หลังคุณกด Save:** ดูบันทึกการทำงานและสถานะการเริ่มใหม่ของ Render ดูข้อผิดพลาดใน Sentry และดูเส้นทางของเคสใน Honeycomb
- **ไม่ต้องแก้ไฟล์ `render.yaml`:** สองแถวนี้ไม่ได้อยู่ในไฟล์นั้น การซิงก์ Blueprint จึงไม่เขียนทับ
